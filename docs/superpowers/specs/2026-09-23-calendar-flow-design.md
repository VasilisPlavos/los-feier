# Flow ημερολογίων — Σχέδιο (design spec)

- **Ημερομηνία:** 2026-09-23
- **Issue:** [#2 Flow για ημερολόγιο](https://github.com/VasilisPlavos/los-feier/issues/2)
- **Αφετηρία:** `2026-09-23-holidays-design.md` (αρχικό σχέδιο). Αυτό το spec αντικαθιστά τα σημεία του για επιλογή ημερολογίου, αλλαγές αργιών «για όλα τα έτη / μόνο για ένα έτος» και εβδομαδιαίο πλάνο.

## 1. Σκοπός

1. Ο χρήστης επιλέγει **πολλά** ημερολόγια αργιών (χώρες, θρησκευτικά κ.λπ.) και, όπου υπάρχουν, **πολλές** περιοχές (regions) ανά ημερολόγιο.
2. Στην πρώτη είσοδο ανοίγει modal επιλογής ημερολογίων.
3. Όλες οι ρυθμίσεις που αφορούν αργίες και εβδομαδιαίο πλάνο ισχύουν **από το έτος που ορίστηκαν και μετά**, μέχρι το επόμενο ρυθμισμένο έτος· το πρώτο ρυθμισμένο έτος καλύπτει και όλο το παρελθόν.

**Κριτήρια επιτυχίας:**
- Νέος χρήστης βλέπει modal με προτσεκαρισμένο το ημερολόγιο της γλώσσας του browser, πατά «Συνέχεια» και βλέπει τις αργίες του.
- Χρήστης επιλέγει «Holidays in Switzerland» (Zurich, Zug) + «Christian Holidays» και βλέπει τις αργίες και των δύο.
- Χρήστης που αλλάζει μια αργία ή το εβδομαδιαίο πλάνο στο 2027 δεν επηρεάζει το 2026 και προηγούμενα· το 2028+ ακολουθεί το 2027.
- Η ένδειξη «από {έτος}» δείχνει πάντα ποιο ρυθμισμένο έτος ισχύει για το έτος που βλέπει ο χρήστης.

## 2. Αποφάσεις

| Θέμα | Απόφαση |
|---|---|
| Τι ακολουθεί τον κανόνα ετών | Ενιαίο **προφίλ έτους**: ημερολόγια, regions, εορτές, αλλαγές αργιών, δικές μου αργίες, εβδομαδιαίο πλάνο |
| Άδειες | Εκτός προφίλ — παραμένουν ανά ημερομηνία |
| Αποθήκευση προφίλ | Πλήρες αντίγραφο (snapshot) ανά ρυθμισμένο έτος |
| Αλλαγή σε μη ρυθμισμένο έτος | Αυτόματο αντίγραφο του προφίλ που το καλύπτει, χωρίς ερώτηση |
| Αλλαγές αργιών | Ανά όνομα αργίας· ισχύουν για όλα τα επιλεγμένα ημερολόγια που έχουν αργία με αυτό το όνομα |
| Modal πρώτης εισόδου | Προαιρετικό· κλείνει και με μηδέν ημερολόγια |
| Settings | Μένει μόνο με γλώσσα, θέμα, export/import, reset |
| Μετάβαση από v1 | Καμία (δεν υπάρχουν χρήστες). Το v1 θεωρείται μη έγκυρο |

## 3. Μοντέλο κατάστασης (AppState v2)

```ts
interface AppState {
  version: 2;
  language: string | null;          // null = γλώσσα συστήματος
  theme: Theme;
  leave: Record<string, Fraction>;  // "YYYY-MM-DD" -> άδεια
  profiles: Record<string, YearProfile>; // "2026" -> προφίλ· {} = πρώτη είσοδος
}

interface SelectedCalendar {
  id: string;        // π.χ. "en.ch"
  regions: string[]; // ταξινομημένα· [] = μόνο εθνικές αργίες
}

interface YearProfile {
  calendars: SelectedCalendar[];            // [] = κανένα ημερολόγιο
  includeObservances: boolean;
  holidayRules: Record<string, HolidayRule>; // όνομα αργίας -> κανόνας
  customHolidays: CustomHoliday[];
  weeklyPlan: WeeklyPlan;
}
```

Φεύγουν: `calendar`, `yearOverrides`, και τα top-level `holidayRules`, `customHolidays`, `weeklyPlan`. Το `ResolvedHoliday` χάνει το `hasYearOverride` και αποκτά `calendarIds: string[]` (από ποια ημερολόγια προέρχεται).

**Προεπιλεγμένο προφίλ** (όταν δεν υπάρχει κανένα): `calendars: []`, `includeObservances: false`, `holidayRules: {}`, `customHolidays: []`, `weeklyPlan: [0,0,0,0,0,1,1]`.

**Schema:** το `validateState` δέχεται μόνο `version: 2`. Κλειδιά του `profiles` πρέπει να είναι ακέραια έτη (4 ψηφία). Οτιδήποτε άλλο (και v1, και import παλιού JSON) απορρίπτεται όπως σήμερα κάθε μη έγκυρο state.

## 4. Λογική

### 4.1 Επίλυση προφίλ (`src/core/profiles.ts`)

- `profileYearFor(profiles, year): number | null` — το μεγαλύτερο κλειδί ≤ `year`· αν δεν υπάρχει, το μικρότερο κλειδί· αν δεν υπάρχουν προφίλ, `null`.
- `profileFor(profiles, year): YearProfile` — το προφίλ του `profileYearFor`, ή το προεπιλεγμένο.
- `editProfile(profiles, year, fn): Record<string, YearProfile>` — αν το `year` δεν είναι κλειδί, αντιγράφει (βαθύ αντίγραφο) το `profileFor(profiles, year)` στο κλειδί `year`· μετά εφαρμόζει το `fn` σε αυτό. Δεν αγγίζει άλλα κλειδιά.

Παράδειγμα με προφίλ `2026` και `2028`: το 2020–2027 χρησιμοποιεί το `2026`, το 2028+ το `2028`. Αλλαγή στο 2024 δημιουργεί `2024` (νέο «πρώτο», καλύπτει ≤2025)· αλλαγή στο 2026 επηρεάζει μόνο 2026–2027.

### 4.2 Reducer

Οι ενέργειες προφίλ παίρνουν `year` (το έτος που βλέπει ο χρήστης) και περνούν από `editProfile`:

```ts
| { type: "setCalendars"; year: number; calendars: SelectedCalendar[]; includeObservances: boolean }
| { type: "setHolidayRule"; year: number; name: string; rule: HolidayRule | null }
| { type: "addCustomHoliday"; year: number; holiday: CustomHoliday }
| { type: "updateCustomHoliday"; year: number; id: string; changes: Partial<Pick<CustomHoliday, "name" | "fraction">> }
| { type: "removeCustomHoliday"; year: number; id: string }
| { type: "cycleWeekly"; year: number; weekday: number }
| { type: "removeProfile"; year: number }
```

- Το `setHolidayRule` χάνει το `scope`. Κενός κανόνας διαγράφει το κλειδί από το `holidayRules` του προφίλ.
- Το `setCalendars` ταξινομεί τα regions κάθε ημερολογίου και αφαιρεί διπλότυπα ids.
- Το `removeProfile` διαγράφει το κλειδί `year` μόνο αν υπάρχει και δεν είναι το μόνο προφίλ· αλλιώς επιστρέφει το ίδιο state.
- Καταργούνται: `setCalendar`, `setRegions`, `setIncludeObservances`.
- `toggleLeave`, `setLanguage`, `setTheme`, `replaceState`, `reset`: ως έχουν.

### 4.3 Αργίες έτους

`resolveYearHolidays(profile, calendars: CalendarFile[], year)`:

1. Για κάθε επιλεγμένο ημερολόγιο που έχει φορτωθεί, κρατά τα events που ταιριάζουν με **τα δικά του** regions (ίδιος κανόνας ορατότητας με σήμερα).
2. Προεπιλογή: ενεργή αν `public` ή αν `includeObservances`, fraction 1. Εφαρμόζεται `holidayRules[name]` του προφίλ.
3. Αν το ίδιο `name` εμφανίζεται την ίδια ημερομηνία σε πολλά ημερολόγια, βγαίνει **μία** εγγραφή με `calendarIds` όλων· τύπος `public` αν έστω ένα είναι `public`, `tentative` μόνο αν όλα είναι `tentative`.
4. Οι δικές μου αργίες του προφίλ προστίθενται όπως σήμερα (χωρίς per-year override).

Το `holidayFractions` και ο υπολογισμός ημερών/σύνοψης μένουν ίδια. Το εβδομαδιαίο πλάνο κάθε ημερομηνίας έρχεται από το `profileFor(profiles, yearOf(date))`, ώστε και τα διαστήματα που περνούν από έτος σε έτος να χρησιμοποιούν το σωστό πλάνο ανά έτος.

### 4.4 Φόρτωση ημερολογίων

`useCalendars(ids: string[])` αντί για `useCalendar(id)`: κάθε αρχείο φορτώνεται μία φορά (cache ανά id), επιστρέφει `{ calendars: CalendarFile[], errors: Record<id, Error>, loading: boolean }`.

- Banner «δεν υπάρχουν δεδομένα για το {έτος}» όταν **κανένα** φορτωμένο επιλεγμένο ημερολόγιο δεν καλύπτει το έτος· αν μόνο κάποια δεν το καλύπτουν, το banner τα ονομάζει.
- Σφάλμα φόρτωσης εμφανίζεται δίπλα στο συγκεκριμένο ημερολόγιο στο `CalendarsPanel`· τα υπόλοιπα λειτουργούν κανονικά.
- Ημερολόγια που βλέπουν τα διαστήματα γύρω από την αλλαγή έτους: φορτώνονται τα ημερολόγια των προφίλ του τρέχοντος, του προηγούμενου και του επόμενου έτους.

### 4.5 Πρώτη είσοδος

Όταν `profiles` είναι `{}` και το index έχει φορτωθεί, ανοίγει το modal (§5.1) σε κατάσταση πρώτης εισόδου, με προτσεκαρισμένο το `suggestCalendarId(navigator.languages)` (αν υπάρχει). «Συνέχεια», × και Esc αποθηκεύουν ό,τι είναι τσεκαρισμένο στο **τρέχον έτος** μέσω `setCalendars` — ακόμα και με μηδέν ημερολόγια — ώστε το modal να μην ξαναβγεί. Το banner `firstRun.*` καταργείται.

## 5. UI

### 5.1 Modal ημερολογίων (`CalendarPickerDialog`)

```
┌ Ημερολόγια αργιών · ισχύουν από το 2026 και μετά ─────── × ┐
│ [🔍 Αναζήτηση…]                                            │
│ ☑ Holidays in Switzerland                                  │  ← επιλεγμένα πρώτα
│ ☑ Christian Holidays                                       │
│ ─────────                                                  │
│ ☐ Διακοπές στην Ελλάδα                                     │
│ ☐ Holidays in Afghanistan  …                               │  ← αλφαβητικά
│                                                            │
│ Περιοχές · Holidays in Switzerland                         │  ← μόνο αν έχει regions
│ [🔍 Αναζήτηση…]   ☐ Επιλογή όλων                           │
│ ☐ Zug   ☑ Zurich   …                                       │
│                                                            │
│ ☐ Να εμφανίζονται και οι εορτές                            │
│                                  [Άκυρο]  [Αποθήκευση]     │
└────────────────────────────────────────────────────────────┘
```

- Οι επιλογές κρατιούνται σε τοπικό draft· «Αποθήκευση» στέλνει **ένα** `setCalendars` για το έτος που βλέπει ο χρήστης. «Άκυρο»/×/Esc (εκτός πρώτης εισόδου) πετά το draft.
- Ο τίτλος δείχνει «ισχύουν από το {year} και μετά», όπου `year` το έτος που βλέπει ο χρήστης.
- Πρώτη είσοδος: τίτλος «Παρακαλώ επιλέξτε ημερολόγια», κουμπί «Συνέχεια», χωρίς «Άκυρο» (§4.5).
- Η λίστα διατάσσεται με τη σειρά που ανοίγει το modal: τα επιλεγμένα πρώτα, μετά τα υπόλοιπα αλφαβητικά (`Intl.Collator` της γλώσσας UI). Δεν αναδιατάσσεται όσο ο χρήστης τσεκάρει.
- Αναζήτηση: χωρίς διάκριση πεζών/κεφαλαίων και τόνων (NFD + αφαίρεση διακριτικών), πάνω στο όνομα του ημερολογίου.
- Περιοχές: μία ομάδα ανά τσεκαρισμένο ημερολόγιο που έχει regions (`calendarRegions`), με δική της αναζήτηση και «Επιλογή όλων» τριών καταστάσεων (`indeterminate` όταν είναι επιλεγμένα κάποια). Το «Επιλογή όλων» επιλέγει/αποεπιλέγει τα regions που ταιριάζουν στην τρέχουσα αναζήτηση. Αν ξετσεκαριστεί ημερολόγιο, χάνονται και τα regions του από το draft. Τα regions ενός ημερολογίου φαίνονται μόλις φορτωθεί το αρχείο του (ένδειξη φόρτωσης μέχρι τότε).
- Native `<dialog>`, focus trap και επιστροφή focus όπως στο σημερινό `SettingsDialog`. Σε κινητό: πλήρης οθόνη, sticky footer με τα κουμπιά.

### 5.2 Section ημερολογίων (`CalendarsPanel`)

Στην αριστερή ζώνη, πάνω από το «Αργίες {year}» (στο κινητό: στην ίδια καρτέλα με τη λίστα αργιών).

```
▸ Ημερολόγια (2) · από 2026                    [Αλλαγή]

▾ Ημερολόγια (2) · από 2026                    [Αλλαγή]
  • Holidays in Switzerland — Zurich, Zug
  • Christian Holidays
  [Κατάργηση ρυθμίσεων 2027]
```

- Αναδιπλούμενο (`<details>`/`<summary>` ή ισοδύναμο button με `aria-expanded`), κλειστό αρχικά· η κατάσταση ανοίγματος θυμάται στο `localStorage` (με try/catch), όχι στο `AppState`.
- «από {Y}» = `profileYearFor(profiles, year)` — αφορά όλο το προφίλ (αργίες και εβδομαδιαίο πλάνο).
- «Κατάργηση ρυθμίσεων {year}» εμφανίζεται μόνο όταν το `year` που βλέπει ο χρήστης είναι ρυθμισμένο **και** υπάρχει άλλο προφίλ· στέλνει `removeProfile`.
- «Κανένα ημερολόγιο · [Επιλογή]» όταν το προφίλ δεν έχει ημερολόγια.
- «Αλλαγή» ανοίγει το `CalendarPickerDialog`.

### 5.3 Λίστα αργιών (`HolidayListPanel`)

- Φεύγουν: το select «Οι αλλαγές ισχύουν για…», το badge «μόνο {year}», το «Αναίρεση της αλλαγής για το {year}», το hint `customAllYearsHint`.
- Κάθε αλλαγή στέλνει `setHolidayRule` / ενέργειες δικών μου αργιών με το `year` που βλέπει ο χρήστης.
- Όταν το προφίλ έχει πάνω από ένα ημερολόγιο, κάθε αργία δείχνει σε δευτερεύον κείμενο το όνομα των ημερολογίων από τα οποία προέρχεται.

### 5.4 Header και Settings

- Το κουμπί με το όνομα του ημερολογίου γίνεται κουμπί ⚙ (`aria-label` «Ρυθμίσεις») που ανοίγει το `SettingsDialog`.
- `SettingsDialog`: γλώσσα, θέμα, export/import, reset. Αφαιρούνται επιλογή ημερολογίου, regions, εορτές.

### 5.5 Εβδομαδιαίο πλάνο

Το `WeeklyPlanPanel` μένει ίδιο οπτικά· διαβάζει το πλάνο από το `profileFor(profiles, year)` και στέλνει `cycleWeekly` με το `year`.

## 6. i18n

- Νέα κλειδιά (en + el) για: τίτλους/κουμπιά του modal (κανονικό και πρώτης εισόδου), αναζήτηση, «Περιοχές · {name}», «Επιλογή όλων», εορτές, `CalendarsPanel` (τίτλος με πλήθος, «από {year}», «Αλλαγή», «Κατάργηση ρυθμίσεων {year}», «Κανένα ημερολόγιο», «Επιλογή»), `aria-label` του ⚙, banner για ημερολόγια χωρίς δεδομένα.
- Αφαιρούνται: `holidays.scope`, `holidays.scopeAll`, `holidays.scopeYear`, `holidays.thisYearBadge`, `holidays.resetYear`, `holidays.customAllYearsHint`, `firstRun.*`, και όσα κλειδιά του Settings αφορούσαν ημερολόγιο/regions/εορτές.
- Το υπάρχον test ισότητας κλειδιών καλύπτει τη συνέπεια.

## 7. Σφάλματα

| Περίπτωση | Συμπεριφορά |
|---|---|
| Αποτυχία φόρτωσης index | Όπως σήμερα· το modal πρώτης εισόδου δεν ανοίγει μέχρι να φορτωθεί |
| Αποτυχία φόρτωσης ενός ημερολογίου | Μήνυμα δίπλα του στο `CalendarsPanel`· οι αργίες των υπολοίπων εμφανίζονται κανονικά |
| Επιλεγμένο id που δεν υπάρχει πια στο index | Εμφανίζεται με το id και ένδειξη σφάλματος· αφαιρείται όταν ο χρήστης αποθηκεύσει το modal |
| Region που δεν υπάρχει πια στο ημερολόγιο | Αγνοείται στην προβολή (όπως σήμερα)· φεύγει στην επόμενη αποθήκευση του modal |
| Αποθηκευμένο state v1 ή μη έγκυρο | Απορρίπτεται, η εφαρμογή ξεκινά με `profiles: {}` (πρώτη είσοδος) |

## 8. Tests

**Unit (Vitest):**
- `core/profiles`: επίλυση πριν το πρώτο / ανάμεσα / μετά το τελευταίο / χωρίς προφίλ· `editProfile` αντιγράφει πριν αλλάξει, δεν αγγίζει άλλα κλειδιά, δεν μοιράζεται αναφορές με το αρχικό.
- `resolveYearHolidays`: πολλά ημερολόγια με διαφορετικά regions· ίδιο όνομα στην ίδια ημερομηνία σε δύο ημερολόγια → μία εγγραφή με `calendarIds`· κανόνας ανά όνομα καλύπτει και τα δύο.
- Εβδομαδιαίο πλάνο ανά έτος σε διάστημα που περνά από 31/12 σε 1/1 με διαφορετικά προφίλ.
- Reducer: κάθε ενέργεια προφίλ δημιουργεί αντίγραφο όταν χρειάζεται· `removeProfile` δεν σβήνει το μόνο προφίλ.
- Schema: v2 έγκυρο· v1, μη ακέραια κλειδιά ετών, λάθος τύποι → απορρίπτονται.
- UI (Testing Library): modal (αναζήτηση με τόνους, regions ανά ημερολόγιο, «Επιλογή όλων» τριών καταστάσεων, «Άκυρο» χωρίς αλλαγή state, κλείσιμο πρώτης εισόδου αποθηκεύει)· `CalendarsPanel` (άνοιγμα/κλείσιμο, «από Y», κατάργηση)· `HolidayListPanel` χωρίς scope· `SettingsDialog` χωρίς πεδία ημερολογίου.
- Ενημέρωση υπαρχόντων tests που βασίζονται σε `calendar`, `yearOverrides`, `scope`, `firstRun`.

**E2E (Playwright, κινητό):**
- Πρώτη είσοδος: modal με προτσεκαρισμένη πρόταση → «Συνέχεια» → αργίες φαίνονται.
- Προσθήκη δεύτερου ημερολογίου και region.
- Αλλαγή αργίας στο επόμενο έτος → το τρέχον δεν αλλάζει, εμφανίζεται «από {επόμενο}», η κατάργηση επαναφέρει.
- Προσαρμογή του υπάρχοντος Greek first-run test στο modal.

## 9. Εκτός scope

- Μετάβαση δεδομένων v1 → v2.
- Συγχρονισμός μεταξύ συσκευών.
- Ιστορικό, μετονομασία ή σύγκριση προφίλ.
- Επιλογή «εφαρμογή σε όλα τα έτη» (ο χρήστης αλλάζει το πρώτο ρυθμισμένο έτος και καταργεί τα επόμενα).
- Ομαδοποίηση ημερολογίων (χώρες / θρησκευτικά) στο modal.
